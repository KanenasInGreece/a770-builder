a770-builder qualifies a local coding model and hands an orchestrator a skill to call instead of an online seat. It admits three engines, llama.cpp, vLLM, and SGLang, on the cards and modes named in the registry (`config/registry/<card>.<mode>.json`). A missing rate in the catalogue stays missing.

```text
your coding agent ── the context, the judgement, the plan
      │  local-build skill (a brief in, a capture out)
      ▼
builder harness ── guard · run lock · budget gate · capture · verify
      │
      ├── bubblewrap sandbox ── opencode ── the seat (a standalone clone of the repository)
      │                          │ loopback bridge, the only network
      └── the model server ────────┘── the compose envelope the profile's backend selects
```

The server runs in a container (`A770B_SERVE=compose`, the only value). Until a profile selects one, the envelope is `compose/a770-vulkan.yaml`. The profile's backend then selects the file, and the env file beside it:

| backend | envelope | what it starts |
|---|---|---|
| `vulkan` | `compose/a770-vulkan.yaml` | llama.cpp, `/app/llama-server`, the full-vulkan image |
| `sycl` | `compose/a770-sycl.yaml` | llama.cpp, `/app/llama-server` after oneAPI, the full-intel image |
| `vllm` | `compose/vllm.yaml` | `vllm serve`, after oneAPI |
| `sglang` | `compose/b70-sglang.yaml` | `python3 -m sglang.launch_server` |

Copy that envelope's `.env.example` to the `.env` next to it and set the image, the DRM nodes, and the host group ids. Start and stop with the skill, by profile name:

```
bash skills/local-build/scripts/local-build.sh serve <profile>
bash skills/local-build/scripts/local-build.sh stop
```

`serve` recreates the container with the profile's argv, so the registry stays the source. The yaml is the envelope: devices, group ids, mounts, the loopback port, and the entrypoint. The VRAM cap and the live-backend sidecar stay on the host. Do not start it with a bare `docker compose up`: that skips the profile argv, the budget gate, the VRAM cap, and the sidecar, and `--no-recreate` would keep the previous model. Every envelope sets `restart: "no"`, so a reboot does not bring the server back. `doctor` warns, without failing, while the selected image is still a floating tag. The speed rung is `harness/bench_http.sh` (llama-benchy, called and not packaged) against the server the load left up. It does not stop that server.

Display and inference are the two modes. Each card's VRAM cap is that host's `A770B_VRAM_CAP_GIB`. The kit (`kit/`, `harness/run_suite.sh`) is what a candidate is qualified against. `kit/PROFILE.md` says how a field is measured.

## Why we made it

Online seats go down, rate-limit, or spend credits on bounded work: a change to named files, tests from a specification, or the read of one large file. The harness measures whether a local model does that work, on the card and the engine the registry names. A fit in VRAM is not that measurement. A pre-built llama.cpp or vLLM image is a different job: [`docs/COMPARISON.md`](docs/COMPARISON.md).

## Install

Clone the repository. Copy `config/builder.env.example` to the builder env file named in [`docs/OPERATING.md`](docs/OPERATING.md), and put the profile's weights in `A770B_MODELS`. Install the skill with `npx skills add KanenasInGreece/a770-builder --skill local-build -g --copy`, or copy `skills/local-build/` into the agent's skill directory. The skill needs this project at `A770B_PROJECT`, plus bubblewrap, uv, and opencode on the host.

```
bash <skill-dir>/scripts/local-build.sh run <brief.md> --profile <profile>
```

Day-to-day running, the knobs, and where the weights come from are in [`docs/OPERATING.md`](docs/OPERATING.md). The project is MIT-licensed (`LICENSE`).

## Security

The worker runs in bubblewrap, with the seat as its only writable tree, no credentials, and no network except the model server on loopback, which requires a key. The guard refuses every live checkout you list, and every linked worktree, symlink, and agent home. Capture executes nothing the model wrote, and `verify` re-runs a capture's tests in a fresh sandbox. The project needs that container, opencode, bubblewrap, socat, uv, and the profile's weights. It needs no database and no account. The seat has no route to any other service on the host. The harness knows of such a service only through two optional knobs, both empty by default: ports the model server must never bind, and a health URL read once before a start. [`SECURITY.md`](SECURITY.md) lists what the harness touches and what you still set yourself.
